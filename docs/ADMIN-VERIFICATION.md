# Admin рөлін тағайындау және тексеру

## Неліктен тіркелу формасында Admin таңдауы жоқ?

Рөлді формадағы hidden field немесе ашық select арқылы қабылдау қауіпті: кез келген адам сұрауды өзгертіп, өзін Admin ете алады. Сондықтан қолданушы тіркелгенде тек сервердің өзі `Student` рөлін тағайындайды.

## Әзірлеу ортасында Admin беру

1. Қосымшаны іске қосып, қарапайым аккаунт тіркеңіз, мысалы `admin-test@example.com`.
2. Қосымшаны тоқтатыңыз.
3. `Program.cs` ішіндегі startup service scope-қа уақытша мына кодты енгізіңіз:

```csharp
var userManager = services.GetRequiredService<UserManager<ApplicationUser>>();
var user = await userManager.FindByEmailAsync("admin-test@example.com");
if (user is not null)
{
	await userManager.AddToRoleAsync(user, "Admin");
}
```

4. Қосымшаны іске қосыңыз және осы Email арқылы қайта кіріңіз.
5. Тексеруден кейін уақытша кодты өшіріп, қайтадан `dotnet build` орындаңыз.

## Тексеру кестесі

| Аккаунт | `/Students` беті | Delete батырмасы | Delete POST |
|---|---|---|---|
| Кірмеген пайдаланушы | Login бетіне бағытталады | Көрінбейді | Орындалмайды |
| Student | Көре алады | Көрінбейді | 403/Access Denied |
| Admin | Көре алады | Көрінеді | Студент жойылады |

## Көзбен тексеру

- Student ретінде кіргенде навигацияда студенттер тізімі ашылады, бірақ жою батырмасы көрсетілмейді.
- Admin ретінде кіргенде `Admin режимі` белгісі және әр студенттің жанында `Жою` батырмасы көрінеді.
- Delete тек POST арқылы орындалады және anti-forgery token қолданады.
- Student сұрау арқылы Delete жіберсе де, `[Authorize(Roles = "Admin")]` серверлік қорғанысы сұрауды қабылдамайды.

## Деректер қорымен тексеру

SQLite Database Browser арқылы:

1. `AspNetUsers` кестесінен пайдаланушы `Id` мәнін алыңыз.
2. `AspNetRoles` кестесінен `Admin` рөлінің `Id` мәнін алыңыз.
3. `AspNetUserRoles` кестесіне `UserId` және `RoleId` мәндерін қосыңыз.
4. Қосымшадан шығып, қайта кіріңіз. Cookie қайта жасалғаннан кейін рөл талаптары жаңартылады.
5. `/Students` бетінде Delete батырмасы пайда болғанын тексеріңіз.
