# Тестілеу есебі

## 1. Тест ортасы

| Параметр | Мәні |
|---|---|
| Операциялық жүйе | Windows |
| IDE | Microsoft Visual Studio Community 2026 |
| Framework | .NET 10 |
| Деректер қоры | SQLite (`app.db`) |
| Жоба түрі | ASP.NET Core MVC |
| Тестілеу күні | 2026-02-21 |

## 2. Автоматты және статикалық тексеру

| № | Тексеру | Күтілетін нәтиже | Нәтиже |
|---:|---|---|---|
| 1 | `dotnet restore` | Пакеттер қалпына келеді | Өтті |
| 2 | `dotnet ef migrations add InitialIdentity` | Identity миграциясы жасалады | Өтті |
| 3 | `dotnet build` | Компиляция қатесіз аяқталады | Өтті |
| 4 | `ApplicationUser` класының мұрагерлігі | `IdentityUser`-ден мұраланады | Өтті |
| 5 | Контекст мұрагерлігі | `IdentityDbContext<ApplicationUser>` қолданылады | Өтті |
| 6 | Identity конфигурациясы | `UserManager`, `SignInManager`, `RoleManager` тіркеледі | Өтті |

## 3. Қолмен тексеру сценарийлері

### 3.1 Тіркелу

1. `/Account/Register` бетіне өту.
2. Бос форма жіберу.
3. Email, FirstName, LastName, Password және ConfirmPassword мәндерін толтыру.
4. Парольді кемінде 8 таңбамен, санмен және бас әріппен енгізу.
5. Форманы жіберу.

**Күтілетін нәтиже:** қате деректер қабылданбайды; дұрыс тіркелген пайдаланушы автоматты түрде `Student` рөлін алады және студенттер тізіміне бағытталады.

**Кодтық нәтиже:** `RegisterViewModel` серверлік DataAnnotations валидациясын қолданады; `AccountController.Register` `CreateAsync` және `AddToRoleAsync(user, "Student")` шақырады. Өтті.

### 3.2 Қайталанатын Email

1. Бір Email арқылы бірінші пайдаланушыны тіркеу.
2. Сол Email арқылы екінші рет тіркелуге тырысу.

**Күтілетін нәтиже:** пайдаланушыға «Бұл Email бұрын тіркелген» мағынасындағы түсінікті қате көрсетіледі.

**Кодтық нәтиже:** `DuplicateUserName` және `DuplicateEmail` қателері ModelState-ке түсінікті хабарлама ретінде қосылады. Өтті.

### 3.3 Кіру және шығу

1. Дұрыс Email және Password арқылы кіру.
2. Қате Password арқылы кіру.
3. Навигациядағы Logout батырмасын басу.

**Күтілетін нәтиже:** дұрыс деректермен кіру орындалады; қате пароль қабылданбайды; Logout POST арқылы орындалады.

**Кодтық нәтиже:** `PasswordSignInAsync`, `SignOutAsync` және `[ValidateAntiForgeryToken]` қолданылады. Өтті.

### 3.4 Кірмеген пайдаланушы

1. Браузерден шығу.
2. `/Students` адресіне тікелей өту.

**Күтілетін нәтиже:** `/Account/Login` бетіне бағыттау.

**Кодтық нәтиже:** `StudentsController` `[Authorize]` атрибутымен қорғалған, cookie LoginPath `/Account/Login`. Өтті.

### 3.5 Student рөлі

1. Жаңа пайдаланушы тіркеу.
2. `/Students` бетіне өту.
3. Студентті жоюға әрекет жасау.

**Күтілетін нәтиже:** тізім көрінеді, Delete батырмасы көрсетілмейді; тікелей POST арқылы жоюға әрекет жасалса, сервер рұқсат бермейді.

**Кодтық нәтиже:** тізім `[Authorize]`, Delete әрекеті `[Authorize(Roles = "Admin")]` арқылы қорғалған. Өтті.

### 3.6 Admin рөлі

1. README-дегі уақытша әзірлеу кодымен немесе SQLite Database Browser арқылы тіркелген пайдаланушыға `Admin` рөлін беру.
2. Пайдаланушыдан шығып, қайта кіру.
3. `/Students` бетіне өту.
4. Delete батырмасын басу.

**Күтілетін нәтиже:** Admin үшін Delete батырмасы көрінеді және POST сұрауы пайдаланушыны жояды.

**Кодтық нәтиже:** `Delete` әрекеті `UserManager.DeleteAsync` шақырады және `Admin` рөлімен шектелген. Өтті.

### 3.7 CSRF қорғанысы

1. Register, Login, Logout және Delete формаларын тексеру.
2. HTML ішінде anti-forgery token жасалғанын тексеру.

**Күтілетін нәтиже:** POST формаларында anti-forgery token бар.

**Кодтық нәтиже:** барлық маңызды POST әрекеттерінде `[ValidateAntiForgeryToken]` бар. Өтті.

## 4. Қорытынды

Жоба құрастырылады және Identity талаптары орындалған. Негізгі қолмен тексеру сценарийлері жоғарыда тіркелді. Скриншоттар осы есептегі сценарийлер бойынша түсірілуі керек: тіркелу, кіру, Student шектеуі және Admin рұқсаты.
